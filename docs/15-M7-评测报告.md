## 15.1 Agent 量化评测（M5）

### 怎么测的

**⚠️ 两类各抽 5 个，而且按活跃度配对。**

只测洗钱案例的话，**一个"见谁都说可疑"的 Agent 会拿满分**。

而第一版抽样就暴露了偏差（dry-run 抓到的）：

```text
不配对：活跃度中位数  洗钱 204 笔 / 正常 62 笔   ← 相差 3.3 倍
```

**原因**：洗钱账户的标注来自注入的模式，而**注入模式本身会产生额外交易**。

**后果**：Agent 可以靠"这个账户的数据多不多"蒙对，而不是靠资金结构。

**配对之后**：`洗钱 204 笔 / 正常 204 笔`——五对全部精确相等。

### 结果

```text
样本 10 个（洗钱 5 / 正常 5）      总耗时 13.4 分钟（平均 80 秒/案例）

  ── 结论质量 ──
  真阳性 TP  5    假阳性 FP  4
  真阴性 TN  0    假阴性 FN  0        ← TN = 0！

  ── 未产出结论（不计入上面任何一格）──
  正常案例没给结论  1

  召回率 100.0%    精确率 55.6%
  误报率 44.4%     真实 FPR **100.0%**

  ── 运行健康度 ──
  产出结论率 90.0%    步数耗尽率 10.0%
  过早结论率  0.0%    强制产出率 10.0%    平均步数 3.00
```

> **Agent 把 5 个正常账户里的 4 个判成「可疑」，剩下 1 个耗尽步数。
> 它从来没能说出「未发现可疑」。FPR = 100%。**

### ⚠️ 但根因不是"模型不行"

**验证了一个假设：被判为"正常"的账户，是不是也有同样"规则"的结构？**

```text
账户           真值    关系数  边数   最大一组
amlsim:2454   洗钱      2    181   180 笔 / 全同 / t=0..199   ┐
amlsim:522    洗钱      2    181   180 笔 / 全同 / t=0..199   ┘
amlsim:156    正常      3     57    19 笔 / 全同 / t=11..194
amlsim:400    正常      1    180   180 笔 / 全同 / t=0..199   ┐
amlsim:32     正常      2     48    24 笔 / 全同 / t=9..198   ┘
```

**`amlsim:2454`（洗钱）和 `amlsim:400`（正常）的结构几乎完全一样**——
都是"一个对手方、约 180 笔、金额全同、`t=0..199`"。

> **所以 Agent 判它可疑不是"模型错了"——
> 而是它看到的结构，在这个数据集里根本不区分好坏。**

**根因**：AMLSim 的**背景交易本身就是高度规则的**。
每个账户都和固定的一组对手方反复转账——
**"结构规则"在这里不是信号。**

### 🎯 由此得到的设计结论

**真正的信号（M3 实测出来的）是**：

| 信号 | 实测 |
|---|---|
| 环长 3 | 约为普通交易的 **40 倍** |
| 金额小 | 单独召回 **90.7%** |

**而这两个 Agent 都拿不到**——因为它**没有基线**：

> 它看到「180 笔、金额全同、t=0..199」，
> **但它不知道这在全图里算多还是算少。**

### ⚠️ 这是一个明确的设计缺口

`docs/14` §14.2 写的是「**三类证据**装配」：

| 证据 | 状态 |
|---|---|
| ① 结构化事实 | ✅ 已接给 Agent（`investigate_account`） |
| ② **算法判断（带实测基线）** | ❌ **没接！** |
| ③ 语义知识 | ✅ 已接（`match_patterns`） |

**`retrieve/fusion.py` 里的 `derive_findings` 和 `MEASURED_SIGNALS` 就是第 ② 类证据**
——它带着「环长 3 是 40 倍、环长 2 是 1.0 倍」这些实测基线，
**但 M5 只把它用在了渲染上，没把它做成工具给 Agent。**

**修法（下一步）**：加一个 `get_detector_scores(account_key)` 工具，
把 M3 检测层的分数（含它在全图中的分位）返回给 Agent。

> **这才是「融合」的完整形态**：
> **Agent 不该从原始事实里"自己看出异常"——
> 异常是相对于基线定义的，而基线在检测层。**

## 15.3 这一轮学到的方法论

### ① **抽样偏差会毁掉整个评测**

「洗钱 204 笔 vs 正常 62 笔」不是细节——**它让 Agent 可以靠数据量蒙对**。

**而它是 dry-run 抓到的，不是跑完之后才发现的。**

> **在花 13 分钟跑评测之前，先花 3 秒检查样本。**

### ② **负面结果要追到根因，否则会误判成"能力不行"**

如果只看到"FPR = 100%"，结论会是「本地小模型不行」。

**而追下去发现**：**是数据里正常账户和洗钱账户结构一样**，
加上 Agent 没有基线——**两个都是可修的问题，不是模型能力问题。**

> **这与产线项目那条教训同源**：
> **「Agent 跑出 0% 检出率，看起来像能力不行，实际是工具设计和步数预算的问题。」**

### ③ **「未产出结论」单独计数，在这一轮救了一次**

那 1 个耗尽的正常案例：

- 折进 `tn` → 精确率会虚高（看起来更好）
- 折进 `fn` → 召回率会虚低（看起来更差）

**两个方向都是错的。** 单独一格才看得清实际发生了什么。
