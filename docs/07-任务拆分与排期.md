# 07 · 任务拆分与排期（WBS）

> **面试被问「你怎么拆任务、怎么排期」——翻这一页。**
>
> 拆任务的本质不是"把活列出来"，而是**找出依赖关系，并把风险最大的部分提前**。

---

## 1. 拆分原则（三条）

| 原则 | 说明 |
|---|---|
| **① 评测真值先行** | **真值和指标框架在第一阶段就建好**，之后每完成一个模块**立刻接入评测**——而不是最后补评测 |
| **② 依赖串行、无依赖并行** | 见下方依赖图 |
| **③ 每个里程碑都有可验收的产出** | 拒绝"完成了 80%"这种说法 |

### 为什么"评测先行"是第一条

> 如果评测最后做，会出现两个后果：
> 1. **每个模块做完时你不知道它有没有用**，只能凭感觉继续；
> 2. 最后发现指标不行时，**已经不知道该改哪一层**。
>
> **评测先行的好处**：图算法做完就有检出率数字，Agent 做完就有端到端数字，
> **哪里掉了能立刻定位到层**。

**这就是我们三层评测体系的价值——它能归因。**

## 3. 里程碑明细

### M1 · 数据与真值准备

| 项 | 内容 |
|---|---|
| **交付物** | 数据集下载脚本；账户/交易解析；**评测真值文件**；指标计算函数 |
| **对应需求** | FR-1 的输入部分 |
| **验收标准** | ① 数据可一条命令获取（不入库）<br>② 真值文件含**每笔交易的模式类型标签**<br>③ 指标函数（召回/精确率/Precision@K/FPR）**有单元测试** |
| **估时** | 3 天 |
| **风险** | 数据集实际字段与预期不符 → **立刻调整 schema，不要硬套** |

> ⚠️ **本阶段就要确认一件事**：数据集自带的模式分类，
> 和我们要检测的 P1–P4 是否对得上。**对不上就要在 PRD 里更正。**

### M2 · 图谱构建

| 项 | 内容 |
|---|---|
| **交付物** | 图 schema 建库脚本；数据导入；索引；**一致性校验脚本** |
| **对应需求** | FR-1 |
| **验收标准** | SRS FR-1 的四条（节点边数对得上、key 唯一、跨行同名未合并、索引命中） |
| **估时** | 4 天 |
| **风险** | 导入性能（百万边）→ 用批量导入而非逐条 `CREATE` |

### M3 · 图算法 + 接入评测 ★

| 项 | 内容 |
|---|---|
| **交付物** | 环路检测、社区发现、中心度；`investigate` 工具；**检测层评测结果** |
| **对应需求** | FR-2 / FR-3 / FR-4 / FR-9 |
| **验收标准** | ① SRS 各条<br>② **拿到第一个真实数字：对注入模式的检出率 vs 规则基线** |
| **估时** | 5 天 |
| **风险** | ⚠️ **环路检测的组合爆炸** → 必须限制长度（`max_length ≤ 8`） |

> **本里程碑结束时的产物，是简历上第一个能写的数字。**

### M4 · 检索与融合（GraphRAG）★

| 项 | 内容 |
|---|---|
| **交付物** | 手法模式库；嵌入与向量检索；`match_patterns`；**融合层**（拼装 LLM 上下文） |
| **对应需求** | FR-5；ADR-0003 |
| **验收标准** | ① Top-1 手法匹配正确率<br>② **消融实验：只用图 vs 只用向量 vs 融合** |
| **估时** | 5 天 |
| **风险** | 模式库规模小（百级），**效果可能不明显** → 若无差异，如实报告，这本身也是结论 |

### M5 · Agent 编排 ★

| 项 | 内容 |
|---|---|
| **交付物** | Plan-and-Execute；4 个受控工具；**强制产出终止条件**；轨迹记录 |
| **对应需求** | FR-6 / FR-7 / FR-8 / FR-10 |
| **验收标准** | ① **未产出结论占比 = 0%**（NFR 目标）<br>② **溯源覆盖率 = 100%**<br>③ 端到端评测数字 |
| **估时** | 5 天 |
| **风险** | ⚠️ 本地模型能力不足 → 备选：换更大本地模型；**但"未产出结论"必须为 0，这是工程问题不是能力问题** |

> ⚠️ **本阶段最容易重演产线项目的坑**：Agent 步数花光空手而归。
> **验收标准里那条"未产出结论 = 0%"就是专门防它的。**

### M6 · 前端与证据展示

| 项 | 内容 |
|---|---|
| **交付物** | 图谱可视化；**证据回链面板**（点结论 → 看到原始交易）；轨迹回放 |
| **对应需求** | NFR-3 的可视化兑现；FR-10 |
| **验收标准** | ① 每条结论**可点击展开原始交易**<br>② 图可交互（缩放、选节点） |
| **估时** | 4 天（可与 M5 并行） |
| **风险** | 图可视化性能（万级节点渲染）→ 只渲染**当前子图**，不做全图 |

### M7 · 部署、CI 与评测报告

| 项 | 内容 |
|---|---|
| **交付物** | Docker Compose 一键起全栈；CI（含**标签泄漏检查**）；README；**三层评测报告** |
| **对应需求** | NFR-4 / NFR-6 / NFR-7 |
| **验收标准** | ① 一条命令起全栈<br>② CI 全绿，**含 NFR-6 的标签隔离检查**<br>③ 评测报告含消融与基线对比 |
| **估时** | 4 天 |
| **风险** | 图库镜像较大 → 分层构建 |

## 4. 排期总览

| 里程碑 | 估时 | 累计 |
|---|---|---|
| M1 数据与真值 | 3 天 | 3 |
| M2 图谱构建 | 4 天 | 7 |
| M3 图算法 + 评测 | 5 天 | 12 |
| M4 检索与融合 | 5 天 | 17 |
| M5 Agent | 5 天 | 22（M6 并行） |
| M6 前端 | 4 天 | 26 |
| M7 部署与报告 | 4 天 | **30 天** |

**约 4.5 周**（含 M5/M6 并行）。

⚠️ **排期要留缓冲**：真实项目里 30 天的工作通常要 35–40 天。
**面试时如果被问"排了多久"**：

> 「我排了 30 天，但**我通常按 40 天报**——因为我做过 6 个生产项目，
> **知道数据准备和联调最容易超期**。」

**主动留缓冲，是靠谱的表现，不是不自信。**

---

## 5. 风险登记册

| 风险 | 影响 | 概率 | 对策 | 触发后的动作 |
|---|---|---|---|---|
| 数据字段与预期不符 | 高 | 中 | M1 先验证 | **改 schema，不硬套** |
| 环路检测性能爆炸 | 高 | 高 | 长度上界 | 已是设计约束 |
| 本地模型能力不足 | 高 | **高** | 换更大模型 | 降级：Agent 只做编排，判断交给算法 |
| 图库导入慢 | 中 | 中 | 批量导入 | — |
| **范围蔓延** | 高 | 中 | **PRD 4.2 的 Out of Scope** | 对照 O1–O9 拒绝 |
| 做成"玩具" | **致命** | 中 | **评测先行** | 没数字的功能不进 README |

## 6. 面试讲法

> 「任务拆分我做了三件事。
>
> **第一，评测真值先行。** 数据集自带模式标签，我在 M1 就把真值和指标框架建好，
> 之后**每完成一个模块立刻接入评测**——图算法做完有检测层数字，
> 检索做完有消融数字，Agent 做完有端到端数字。**这样哪里掉了能立刻定位到层**，
> 而不是最后发现指标不行却不知道改哪。
>
> **第二，我把风险最大的放前面。** 数据能不能用是最大不确定性，所以 M1 就验证；
> 环路检测的组合爆炸是已知的，所以直接做成参数上界。
>
> **第三，排期我留了缓冲。** 我排 30 天，但按 40 天报——
> 因为我做过 6 个生产项目，**知道数据准备和联调最容易超期**。」
